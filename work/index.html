정책 문서와 변경 이력 관리

운영 규칙을 화면 시안 안에 기재하면 화면이 변경될 때 규칙이 함께 유실될 수 있습니다. 상태값, 권한, 예외 처리는 화면과 분리된 Markdown 문서로 작성하고, 변경 내용은 Git 커밋으로 관리합니다. 이 사이트의 엘릭서 정책 문서가 그 예시입니다.

문서다루는 내용
01 상태값 정의기기 상태값의 종류와 정의, 중복 시 표시 우선순위열기
02 권한 매트릭스계정 단계별 조회 범위와 기능 권한열기
03 입력 규칙 · 예외 처리입력 조건, 제한 상황별 처리 방식과 화면 내 안내열기
04 고장 신고 → 조치신고부터 완료까지의 단계별 담당자와 처리 절차열기
변경 이력변경 일자, 변경 내용, 변경 사유열기

엘릭서에서는 앱 버전별 사양을 Git으로 관리했습니다.

컨펌 절차 설계 (Jira)

엘릭서 팀은 기획, SW, HW, 그래픽 네 파트가 한 Jira에서 일했습니다. 담당자가 직접 "완료"로 전환할 수 있으면 검토되지 않은 작업이 누적되므로, "완료" 전환 경로를 컨펌 승인 하나로 제한하고 전후 단계를 자동화했습니다.

작업 상태 전환사용자 조작자동 처리

완료 경로 단일화

"완료" 상태로의 전환은 컨펌 승인으로만 가능합니다. 반려 시에는 사유 작성을 필수로 했습니다.

상태 전환 자동화

PR을 생성하면 작업이 컨펌 대기로 자동 전환되고 컨펌 담당자에게 알림이 전송됩니다. PR 링크는 댓글로 자동 등록됩니다.

단계적 적용

1개 스프린트에 먼저 적용하고 회고를 거친 뒤 4개 파트 전체로 확대했습니다.

같은 Jira에서 5개년 로드맵과 2주 스프린트를 함께 운영했습니다. Blocker · Critical 작업에는 표시가 자동으로 추가되고 PM에게 알림이 전송됩니다.

AI Agent 활용

AI Agent는 기획자가 정한 구조를 빠르게 제작하고 검증하는 용도로 활용합니다. 제작 대상과 사실 여부는 직접 판단하고, 제작 속도를 AI로 높입니다.

AI 프로젝트 보기

이 포트폴리오의 제작 과정

  1. 사실 정리프로젝트별 기간, 역할, 결과를 지식베이스에서 확인
  2. 구조 결정전달할 내용과 도식 형태를 직접 결정
  3. 제작도식과 ADMIN 시안을 Claude Code로 제작
  4. 검토출처에 없는 내용과 추정은 삭제하거나 수정
