# 엘릭서 ADMIN 정책 문서

엘릭서(비침습 혈당 측정 기기) 운영 화면의 정책을 화면과 분리해 Markdown으로 정리한 문서입니다.
화면이 바뀌어도 규칙은 이 문서 한 곳에서 고치고, 고친 이력은 Git 커밋으로 남깁니다.

> 실제 기획서를 공개 범위에 맞게 다시 정리한 것입니다. 고유번호 형식, 금액, 오류 코드처럼 구체적인 값은 예시입니다.

## 문서 지도

```
docs/
├─ README.md                 지금 이 문서
├─ CHANGELOG.md              문서 변경 이력
└─ elixir/
   ├─ 01-states.md           상태값 정의 (운영 상태 · 기기 상태)
   ├─ 02-permissions.md      권한 매트릭스 (SUPERALL · SUPERVISOR · VISOR)
   ├─ 03-exceptions.md       입력 규칙 · 예외 처리
   └─ 04-fault-flow.md       고장 신고 → 조치 플로우
```

## 읽는 순서

```
01 상태값 ──▶ 02 권한 ──▶ 03 예외 처리 ──▶ 04 고장·A/S 플로우
 무엇이 있나    누가 바꾸나    막히면 어떻게 되나    한 건이 끝까지 가는 길
```

| 문서 | 답하는 질문 |
|---|---|
| [01 상태값 정의](elixir/01-states.md) | 기기 한 대가 가질 수 있는 상태는 무엇이고, 겹치면 무엇이 먼저인가 |
| [02 권한 매트릭스](elixir/02-permissions.md) | 누가 어디까지 보고, 무엇을 바꿀 수 있는가 |
| [03 입력 규칙 · 예외 처리](elixir/03-exceptions.md) | 잘못 입력하거나 조건이 안 맞으면 화면이 어떻게 답하는가 |
| [04 고장 신고 → 조치](elixir/04-fault-flow.md) | 고장 한 건이 신고부터 완료까지 누구 손을 거치는가 |

## 용어

| 용어 | 뜻 |
|---|---|
| SUPERALL | 본사 운영 계정. 전체 지역과 전체 기기를 본다 |
| SUPERVISOR | 지역을 맡은 계정. 자기 지역의 기기만 본다 |
| VISOR | 기기 한 대에 연결된 현장 계정. VISOR 하나가 기기 한 대다 |
| 운영 상태 | 계약과 권한 때문에 측정이 되는지 안 되는지 |
| 기기 상태 | 기기 자체가 멀쩡한지 고장인지 |
