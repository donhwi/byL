# 04. 고장 신고 → 조치 플로우

현장(VISOR)에서 고장을 알리면 지역(SUPERVISOR)이 먼저 받고, 지역에서 풀 수 없으면 본사(SUPERALL)로 넘깁니다.

## 1. 단계

```
① 신고 접수 ──▶ ② 조치 예정 안내 ──▶ ③ 조치 중 ──▶ ④ 완료
   VISOR           SUPERVISOR            SUPERVISOR      기기 상태 정상 복귀
                   (또는 SUPERALL)       (또는 SUPERALL)
```

| 단계 | 누가 | 하는 일 | 기기 상태 |
|---|---|---|---|
| ① 신고 접수 | VISOR | 유형을 고르고 문제 내용을 적어 제출 | 비정상으로 전환 |
| ② 조치 예정 안내 | SUPERVISOR | 조치 방법과 예정일을 정해 등록. VISOR 화면에 표시 | 비정상 |
| ③ 조치 중 | SUPERVISOR | 조치를 진행 | 비정상 |
| ④ 완료 | SUPERVISOR | 완료 처리 | 정상으로 복귀 |

## 2. 담당이 바뀌는 경우

```
VISOR ──신고──▶ SUPERVISOR ──직접 처리──▶ 완료
                    │
                    └─넘기기─▶ SUPERALL ──처리──▶ 완료
```

- 신고가 들어오면 SUPERVISOR와 SUPERALL 양쪽에 알림이 갑니다. 처음 담당은 SUPERVISOR입니다.
- SUPERVISOR는 완료 전 단계에서 언제든 SUPERALL로 넘길 수 있습니다.
- 넘긴 뒤에는 SUPERALL만 단계를 진행할 수 있습니다.

## 3. 조치 방법

| 방법 | 쓰는 경우 |
|---|---|
| 원격 안내 | 현장에서 설명을 듣고 직접 해결할 수 있을 때 |
| 출장 수리 | 사람이 가서 고쳐야 할 때 |
| 기기 교체 | 수리로 해결되지 않을 때 |

## 4. 각 계정이 보는 화면

| 시점 | VISOR | SUPERVISOR | SUPERALL |
|---|---|---|---|
| 신고 직후 | "담당 SUPERVISOR가 내용을 확인하고 있습니다" | 새 신고, 조치 계획 입력 | 새 신고 (보기) |
| 조치 계획 등록 후 | 조치 방법과 예정일 | 단계 진행 | 보기 |
| SUPERALL로 넘긴 후 | 조치 방법과 예정일 | "SUPERALL이 맡아 처리하고 있는 건" | 조치 계획 입력, 단계 진행 |
| 완료 | 기기 상태 정상 | 완료 | 완료 |

## 5. 예외

| 상황 | 처리 |
|---|---|
| 신고 없이 VISOR가 기기 상태만 비정상으로 바꿈 | 상위 계정에 알림만 감. 신고 건은 만들어지지 않음 |
| 조치가 끝나기 전에 VISOR가 기기 상태를 정상으로 되돌림 | 진행 중인 신고를 완료 처리 |
| 문제 내용이 5자 미만 | 제출 불가 |
